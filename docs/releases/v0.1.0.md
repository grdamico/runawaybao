# RunawayBao v0.1.0 — Controlled Runtime Credential Enforcement (Lab Preview)

RunawayBao is an experimental Go prototype tested in a disposable Docker Desktop
cgroup v2 lab. Its first preview demonstrates how a verified workload identity
and a runtime policy finding can be used to revoke the exact OpenBao lease
issued to that workload.

**Dry-run is the default.** Enforcement requires a separate local command and
interactive confirmation of the disposable OpenBao target and fresh run
reference. The policy evaluator remains independent of enforcement and emits
audit-only recommendations.

## Implemented capabilities

| Milestone | Capability |
| --- | --- |
| M1 | Go job authorization and restricted OpenBao KV reads |
| M2 | Dynamic PostgreSQL credentials with per-job leases and exact-lease revocation |
| M3 | Tetragon process-event correlation with deduplication and observation-gap tracking |
| M4 | Deterministic executable-path allowlists and sanitized dry-run policy findings |
| M5 | Restricted containerized PostgreSQL workers with isolated networks and bounded attached-stdin credential delivery |
| M6A | Strong identity using event-time PID and cgroup namespaces, pinned namespace objects, and trusted Docker execution-generation metadata |
| M6B | Operator-confirmed exact-lease enforcement with a protected operation journal and independent PostgreSQL verification |

## Live verification

In the operator-confirmed WSL run, Tetragon correlated Job B’s harmless helper
to B’s verified workload generation. The pinned allowlist classified the
execution as suspicious. OpenBao acknowledged one synchronous request for B’s
original lease. A separate fresh PostgreSQL authentication check rejected B’s
original credentials before natural expiry. Job A authenticated and completed
the fixed read with its original credentials.

The run also verified credential redaction, owned-resource cleanup, and natural
expiry of remaining observation leases. The publication review found one
authorized, dispatched, and acknowledged journal operation with zero unresolved
entries. A separate default dry-run preserved both job credentials and issued
zero event-driven revocation requests.

## Reproduce in a disposable lab

After checking out tag `v0.1.0`, use Go 1.22 or newer, Bash, and Docker Desktop
with WSL integration, cgroup v2, and compatible eBPF/BTF support. Configure the
ignored local `.env` with disposable values as described in the
[testing guide](https://github.com/grdamico/runawaybao/blob/v0.1.0/docs/testing.md#getting-started).

```bash
test -f .env || cp .env.example .env
chmod 600 .env
./scripts/start.sh
./scripts/status.sh
./scripts/test-container-database.sh
./scripts/test-container-database.sh identity
```

Run these suites sequentially. To run the separate live enforcement test, use
your active WSL terminal and a protected journal outside the repository:

```bash
install -d -m 700 "$HOME/.local/state/runawaybao"
./scripts/test-container-database.sh enforce   "$HOME/.local/state/runawaybao/enforcement.jsonl"
```

Enter the exact target line printed by the test within two minutes. The test
creates its restricted revoker token only after confirmation. An expired prompt
requires a fresh invocation. Retain the private journal as reconciliation
evidence. Standard CI compiles the live tests and runs unit and race checks.

## Security and operational limits

- This preview assumes a trusted local host, Docker daemon, controller,
  privileged Tetragon agent, and local OpenBao and PostgreSQL services. OpenBao
  runs in development mode and PostgreSQL uses disposable fixture data.
- Executable paths can produce false positives and cannot establish binary
  integrity or intent. Observation gaps can withhold enforcement. Silent
  upstream event loss remains possible.
- Workload lifecycle state is in memory. The protected journal records dispatch
  intent and outcomes. Ambiguous outcomes require manual reconciliation, and
  local durability cannot guarantee exactly-once remote revocation.
- The database check covers fresh authentication. Existing PostgreSQL sessions
  can outlive revocation.

See the [security model](https://github.com/grdamico/runawaybao/blob/v0.1.0/docs/security-model.md)
and [demonstration guide](https://github.com/grdamico/runawaybao/blob/v0.1.0/docs/demo.md)
for operational details. Treat this release as a lab preview.
